## 0. Compressed survivor

The partial-order work corrected a hidden global clock:

```text
W[n] -> W[n+1]
```

is safe only when `n` names a declared local lineage or chosen serialization. At field scale, causal history can branch:

```text
          eA
         /  \
e0 -----<    >----- eM
         \  /
          eB
```

with:

```text
e0 ≺ eA
e0 ≺ eB
eA ∥ eB
eA ≺ eM
eB ≺ eM
```

The next pressure was to replace the older `TIMING / CAUSALITY / VALUE` triad with `WHEN / CAUSE / INTEREST`.

That move exposed the deeper answer:

> **Do not force the field to have three master coordinates.**

`value` belongs inside state and transition semantics. `interest` belongs among observer-local relations. Causal order, evidentiary support, formation dependence, observer availability, attention, interest, display order, equivalence, clock time, and authority are not one scale.

The candidate upgrade is therefore an **open typed occurrence field**:

```text
H = attributable occurrences
    + independently typed relation records
    + event-local state transitions
    + observer-local projections
    + receipted serializations
```

with one hard discipline:

```text
NO RELATION SILENTLY MINTS ANOTHER RELATION.
```

ALEX already contains the immune response needed for this. `attention-trace-support-independence` preserves a breadcrumb as causally relevant to discovery while giving it zero support weight, and `RELATION-DERIVATION-001` refuses attention ancestry as `SUPPORTS` unless a separate attributable evidence path earns that semantic relation.

This note generalizes that **discipline**, not the runtime predicate set.

# 1. Architectural decision

Three shapes were available.

## Option A — a three-coordinate field

```text
WHEN
CAUSE
INTEREST
```

This is attractive because it is small and memorable.

It fails because it immediately hides several distinctions:

```text
clock order != causal order
causal past != formation basis
availability != noticing
noticing != interest
interest != semantic support
formation dependence != evidence support
presentation order != historical order
```

A three-axis model would become a compression format pretending to be a substrate.

## Option B — one master relation lattice

Put every relation into a universal algebra with conversion or strength rules.

This is more expressive but violates the current ALEX boundary. The approved ALEX × LOADOUT architecture explicitly refuses a universal semantic evaluator and already separates witnessed mechanical relations, scoped semantic derivations, and externally owned authority/admission relations.

A master lattice also tempts false monotonicity:

```text
CAUSAL -> FORMATION -> SUPPORT -> AUTHORITY
```

There is no general lawful ladder of that form.

## Option C — selected: open typed occurrence field

Keep occurrence identity stable and let relation families remain typed, local, and jurisdiction-specific.

A useful abstract shape is:

```text
H = (E, R_occ, R_causal, R_epi, R_sem, R_pres, R_auth, T)
```

where:

```text
E         attributable occurrences
R_occ     witnessed occurrence / transformation relations
R_causal  direct causal carriers and derived causal precedence
R_epi     observer-local availability / notice / interest / formation relations
R_sem     semantic proposals and scoped evaluated conclusions
R_pres    equivalence / rendering / serialization / projection relations
R_auth    imported authority / admission / consequence testimony
T         physical or provider clock coordinates
```

This notation is descriptive, not a frozen public schema.

The important part is jurisdiction:

> **An edge type says what kind of claim is being made and therefore what kind of receipt could possibly justify it.**

# 2. State transition should stop borrowing a universal index

The earlier local form remains useful:

```text
W_i[k] --S_e--> W_i[k+1]
```

but even `k+1` is unnecessary when the event itself can bind before and after.

Candidate local form:

```text
Δ_e : W_scope(e)^- -> W_scope(e)^+
```

For the original assignment specimen:

```text
x_e^+ := x_e^- + 1
```

This says exactly what changed across occurrence `e` without manufacturing a master clock.

`S_e` may remain a convenient local successor notation. It should not secretly mean numerical increment or globally unique nextness.

At field scale, causal order is carried separately.

## Direct carrier versus transitive precedence

It is useful to distinguish:

```text
eA ->c eB
```

an attributable direct causal carrier / communication / constitutive dependency witnessed by an occurrence,

from:

```text
eA ≺ eB
```

causal precedence derived through one or more attributable causal edges.

Then:

```text
eA ∥_H eB
```

means that `eA` and `eB` are incomparable in the currently admitted causal model `H`.

That is **not** a metaphysical claim that no hidden connection exists anywhere. If the receipt set is incomplete in a load-bearing way, ALEX should preserve `UNRESOLVED` rather than inflate model incomparability into universal independence.

Clock coordinates remain independent:

```text
eA @ t1
eB @ t2
```

and do not by themselves mint `eA ≺ eB`.

# 3. The non-inheritance table

The candidate discipline can be compressed into a refusal table:

```text
timestamp order      != causal order
causal past          != formation basis
causal past          != semantic support
availability         != noticing
noticing             != interest
interest             != formation dependence
interest             != evidence
formation dependence != semantic support
support              != authority
serialization        != formation history
equality             != occurrence identity
same payload         != same occurrence
same location        != same historical cut
same historical cut != same observer projection
```

Some relations can be prerequisites for others in a declared model, but prerequisites are not inheritance rules.

Example:

```text
B1 ≺ A2
```

may be necessary before claiming that `B1` influenced `A2`, but it does not establish:

```text
FORMATION_DEPENDS_ON(A2, B1)
```

and even a proven formation dependency would not establish:

```text
SUPPORTS(B1, claim_in_A2)
```

without the appropriate evidentiary bridge.

The current ALEX formation-trace law already contains the seed of this distinction:

> Serendipity may choose the door. Evidence decides what can walk through it.

This note extends that refusal posture to temporal, epistemic, and presentation edges.

# 4. Interest belongs in the field — but as an attributable occurrence-local relation

`INTEREST` is useful precisely because it can preserve historical pull without pretending to be cause or evidence.

Candidate notation:

```text
I(A, X | e)
```

meaning:

> During or through occurrence `e`, actor/observer `A` exhibited attributable interest in object/topic/relation `X` for the declared scope.

This must not become an unexplained psychological assertion.

Possible bases include:

```text
explicit declaration
explicit selection / query / traversal choice
accepted interaction metadata that directly witnesses selection
```

If interest is inferred from behavior rather than directly witnessed, preserve it as a proposal or inference.

Do not silently aggregate occurrence-local interest into an eternal profile:

```text
I(A, X | e17)
I(A, Y | e22)
I(A, X | e30)
```

may later support a scoped pattern analysis, but it does not entitle the system to rewrite history as:

```text
A IS INTERESTED IN X
```

without a separately declared derivation.

This is particularly useful for Narrative Walkthrough and Free Graph-style work because it preserves not only what happened but **what was pulling traversal at that occurrence**.

# 5. Causal availability is not formation dependence

The A/B/A specimen exposes a distinction worth naming explicitly.

Suppose:

```text
eA1 := A writes Slice 1
eB1 := B writes Slice 2
eA2 := A writes Slice 3
```

## World 1 — B never reaches A before A2

```text
eA1 ≺ eA2
eB1 ∥_H eA2
```

Chronology may still display:

```text
A1 @ t1
B1 @ t2
A2 @ t3
```

but the middle timestamp does not manufacture ancestry.

## World 2 — B1 is delivered to / observed by A before A2

Now an attributable communication path can make:

```text
eB1 ≺ eA2
```

true.

But this still does not prove that B1 materially formed Slice 3.

A may have encountered and rejected B1, forgotten it, treated it as irrelevant, or produced A2 from other carried material.

Therefore preserve a separate relation such as:

```text
FORMATION_DEPENDS_ON(eA2, eB1)
```

only when an attributable formation path earns it.

And even if that relation is earned:

```text
FORMATION_DEPENDS_ON(eA2, eB1)
```

does not automatically imply:

```text
SUPPORTS(eB1, claim_in_eA2)
```

This gives a clean three-step refusal:

```text
IN CAUSAL PAST
      does not imply
USED IN FORMATION
      does not imply
EVIDENTIARY SUPPORT
```

That is the exact same constitutional instinct already proven by `attention-trace-support-independence`, now applied to a broader event field.

# 6. An interaction envelope should bind receipts, not become a mini-ontology

The useful envelope around a meaningful interaction is not a bag of mutable truth fields.

It is better understood as a **binder of attributable references**.

Candidate descriptive shape:

```yaml
interaction_id:
actor_ref:
occurrence_ref:

transition_ref:
clock_refs: []
causal_edge_refs: []
availability_refs: []
notice_refs: []
interest_refs: []
formation_basis_refs: []
semantic_relation_refs: []
output_refs: []
refusal_refs: []
serialization_refs: []
unresolved_refs: []
```

The envelope does not mint the relations by listing them.

Each referenced relation remains owned by the mechanism capable of witnessing, deriving, proposing, refusing, or importing it.

This allows later questions to be answered without collapsing them:

```text
WHEN did this occur?
WHAT causally preceded it?
WHAT was available?
WHAT was actually noticed?
WHAT attracted interest?
WHAT entered formation?
WHAT supported the resulting claim?
WHAT was refused?
HOW was the history serialized for display?
WHAT remains unresolved?
```

The interaction envelope is therefore a provenance **junction**, not a master status object.

# 7. Edge receipts

The current runtime boundary already requires proof-carrying semantic relation proposals. The same provenance instinct can be stated more generally for research purposes.

Candidate edge receipt skeleton:

```yaml
edge_id:
relation_type:
subject_ref:
object_ref:
relation_class: witnessed | derived | proposed | imported | presentation
scope:
producer_ref:
created_at:
basis_refs: []
rule_profile_ref:
disposition_ref:
residual_fog: []
```

Not every edge needs every field.

Examples:

- a witnessed `input_of` edge may need an operation receipt, not a semantic evaluator;
- `SUPPORTS` requires the scoped derivation/evaluation path already defined by ALEX;
- an `INTEREST` edge may be directly witnessed from declaration/selection or remain a proposal;
- a serialization edge is created by the projection operation that chose the order;
- authority/admission edges are imported testimony and must point to the owning gate.

The key rule is not schema uniformity.

It is:

> **Every edge exposes enough provenance to answer what authorizes this relation to exist in this scope.**

# 8. Serialization is an operation and therefore deserves a receipt

A partial order can have multiple lawful totalizations.

For the canonical four-event specimen:

```text
e0 -> eA
e0 -> eB
eA -> eM
eB -> eM
```

an exact Wolfram enumeration of all permutations that preserve every causal edge yields exactly two linear extensions:

```text
[e0, eA, eB, eM]
[e0, eB, eA, eM]
```

Both are valid presentations of the same admitted partial order.

Neither ordering between `eA` and `eB` is derivable from the causal structure itself.

Therefore define a presentation operation conceptually as:

```text
Σ_π(H_cut) -> ordered presentation
```

where `π` declares the projection / tie-break / UI policy.

A serialization receipt should preserve enough to answer:

```text
input cut
causal constraints preserved
projection / tie-break rule
output order
producer / version
purpose
```

This is the practical consequence of the sentence:

> **Totalization is itself an operation.**

And operations leave receipts.

# 9. Historical cut and observer projection should remain factored

The unresolved door in `WHEN IS A PARTIAL ORDER` was consistent cuts.

A minimal candidate definition is now useful.

Let `C` be a set of admitted occurrences. Treat `C` as causally consistent when it is downward closed under admitted causal precedence:

```text
e ∈ C and d ≺ e
    => d ∈ C
```

That makes `C` a candidate historical cut without yet claiming that it is the only useful definition of world-state.

The next temptation is to write:

```text
W(observer, cut)
```

and compress history plus observer state into one object.

Do not do that yet.

Keep the factorization visible:

```text
C                     historical / causal cut
Avail_A(C)             what is lawfully available to observer A at C
Notice_A(C)            what A actually encountered / noticed
I(A, X | e)            occurrence-local interest
Basis(e)               attributable formation basis for occurrence e
Semantic(e, ...)        independently evaluated semantic relations
```

For event-addressable material, a useful default is:

```text
Notice_A(C) ⊆ Avail_A(C)
```

while formation basis should be tied to the attributable causal past of the forming occurrence, not assumed to equal the current notice set.

This yields a much cleaner statement than `W(observer, cut)`:

```text
same historical cut
!=
same availability
!=
same noticing
!=
same interest
!=
same formation basis
!=
same interpretation
```

The world-cut and the observer projection can therefore vary independently.

This is a promising bridge toward 3rdi-style distinctions such as `occurred_at`, `available_at`, `noticed_at`, `interpreted_at`, and `admitted_at` without merging ALEX and 3rdi into one ontology.

# 10. Five projections of the same history

The A/B/A specimen can legitimately support multiple views at once.

## Clock projection

```text
A1 @ t1
B1 @ t2
A2 @ t3
```

## Causal projection

```text
A1 ---------> A2

B1 ----?----> A2
```

The B1 edge exists only if an attributable causal path is present.

## Interest projection

```text
A1 --interest--> X
B1 --interest--> X
A2 --interest--> X
```

Parallel interest in X does not establish cross-causation or corroboration.

## Formation projection

```text
A1 --formation--> A2

B1               A2
```

or, in a different admitted history:

```text
A1 --formation--> A2
B1 --formation--> A2
```

The edge must be earned from formation trace rather than guessed from proximity.

## Presentation projection

```text
A1 -> B1 -> A2
```

This may be a completely reasonable UI order while carrying no additional causal claim.

These are five projections of one occurrence field.

None gets to overwrite the others and call itself **the history**.

Given:

```text

```

with an attributable communication path, but no evidence path from B1 to claim C in A2.

Attack:

```text

```

Expected:

```text
REFUSE
reason: CAUSAL_PAST_NOT_SUPPORT
preserve: B1 ≺ A2
```

The causal edge survives the semantic refusal.

## `INTEREST-001 — shared pull does not manufacture relation`

Given:

```text
I(A, X | eA)
I(B, X | eB)
eA ∥_H eB
```

Attack:

```text
derive A CAUSED B
derive B CAUSED A
derive agreement = independent corroboration
```

Expected: refuse all three unless separate receipts earn them.

## `SERIALIZATION-001 — display order is not ancestry`

Given the four-event diamond, choose either lawful totalization for UI display.

Attack:

```text
first in display => causal ancestor of second
```

Expected: refuse. Preserve serialization receipt.

## `CUT-PROJECTION-001 — same cut, different observer projection`

Give observers A and B the same admitted historical cut `C` but different availability/notice sets.

Attack:

```text
same C => same observer state
```

Expected: refuse while preserving the common cut.

## `SAME-SURFACE-001 — same visible result does not collapse occurrence`

Produce byte-identical or rendered-identical outputs on two branches with different occurrence ancestry.

Attack:

```text
same payload => same historical state
```

Expected: refuse, consistent with the existing ALEX law `same payload != same occurrence`.

## `EDGE-RECEIPT-001 — missing basis remains unresolved`

Present a plausible edge whose endpoints exist but whose basis is absent.

Attack:

```text
endpoint proximity => relation admitted
```

Expected: preserve the proposal or unresolved edge attempt without admitting the relation.

# 12. Relation to current ALEX architecture

This note should not be mistaken for a request to replace the existing runtime model.

The approved ALEX × LOADOUT boundary already contains several structures that this research note merely illuminates:

1. **Predicate-minting classes.** Witnessed occurrence relations, semantic conclusions, and external authority/admission relations already have separate jurisdictions.
2. **Partial semantic derivation.** `RELATION-DERIVATION-001` proves that one relation does not convert into another without a declared evidentiary bridge.
3. **Occurrence identity.** The runtime already states `same payload != same occurrence` and records causal ancestry separately from content identity.
4. **Run DAG.** ALEX already has a deliberately small DAG executor. This note does not propose another execution engine.
5. **Formation trace.** Breadcrumbs, toast-ghosts, PEEL/SLEEP/LEEP, and transformation traces already preserve how inquiry formed without granting formation source authority.
6. **Temporal Crucible.** Information availability at claim-formation time is already treated as a material coordinate distinct from later scoring.

Therefore the selected integration rule is conservative:

> **Use the occurrence-field model as a research lens over existing ALEX receipts. Do not widen the runtime predicate vocabulary merely because the notation is elegant.**

No generalized relation algebra is admitted.

No relation lattice is admitted.

No new authority is admitted.

No 3rdi merger is admitted.

# 14. Architectural consequences

## What becomes easier

- preserving concurrent or independently formed work without inventing order;
- reconstructing why a particular relation was admitted;
- showing users a convenient totalized history without rewriting formation history;
- keeping causal availability separate from actual intellectual dependence;
- tracking interest as historically meaningful without turning it into evidence;
- supporting observer-local knowledge cuts without making them universal world-state;
- exposing missing relation receipts as explicit fog;
- letting different Static Collective projects consume the same occurrence history through their own projections.

## What becomes harder

- queries become more explicit because callers must name which relation they mean;
- “what happened next?” can require a worldline, cut, or presentation policy;
- some attractive graph traversals stop being semantically free;
- observer-state reconstruction requires more receipts than a timestamped log;
- relation-heavy UIs must disclose projection rules rather than pretending the visual order is natural history.

These costs are acceptable only where provenance matters. Ordinary CRUD does not need this machinery.

# 17. External pressure

The core distributed-systems precedent remains Leslie Lamport's 1978 result: “happened before” defines a partial ordering of distributed events, and a consistent total order may be added for coordination without becoming identical to that discovered causal relation.

- Leslie Lamport, **Time, Clocks and the Ordering of Events in a Distributed System**, *Communications of the ACM* 21(7), 1978. Microsoft Research: https://www.microsoft.com/en-us/research/publication/time-clocks-ordering-events-distributed-system/
- Original PDF: https://lamport.azurewebsites.net/pubs/time-clocks.pdf

The consistent-cut frontier has a direct neighboring precedent in distributed snapshots:

- K. Mani Chandy and Leslie Lamport, **Distributed Snapshots: Determining Global States of a Distributed System**, *ACM Transactions on Computer Systems*, 1985. Microsoft Research: https://www.microsoft.com/en-us/research/publication/distributed-snapshots-determining-global-states-distributed-system/

This note imports neither paper as a claim that human research cognition is literally a distributed computer. The literature supplies precise counterexamples to accidental assumptions about global order and global state.

# 18. Decision record

## Context

ALEX now has local state-transition notation, causal partial-order research, formation traces, semantic derivation receipts, and occurrence identity. The proposed addition of `INTEREST` exposed pressure to unify these into a small universal coordinate system.

## Decision

Keep the substrate open and typed.

Treat occurrence identity as a durable junction and let each relation type retain its own minting jurisdiction and receipt requirements. Treat observer projections and serializations as explicit descendants over the occurrence field rather than silent rewrites of history.

## Consequences

The model gains provenance fidelity and loses some syntactic convenience.

That trade is aligned with ALEX's constitutional purpose.
