## Why this method exists

Decoder work often jumps too quickly to:

> Which decoder is correct?

MADDCL0WN asks a prior PRESSURE question:

> **WHAT CHANGES WHEN THE KEY CHANGES?**

Hold a source fixed. Perturb one declared decoder feature. Compare the projections. Repeat under hostile and alternate keys. Preserve what burns, what bifurcates, what interacts, and what survives.

A wrong decoder may therefore be a useful **control** without becoming evidence for its own reading.

## Classify the burn

### ASH

A favored property disappears under relevant perturbation.

```text
DECODER_FRAGILE
```

### RECURRENCE

The property appears under several decoder variants.

```text
RECURS
```

Recurrence does not imply independence if the decoder family shares load-bearing assumptions.

### BIFURCATION

A small decoder change creates a large or type-changing projection difference.

```text
DECODER_BOUNDARY
```

### INTERACTION

Two decoder changes jointly produce a difference not attributable to either first-order change alone under the declared calculus.

```text
INTERACTION_CANDIDATE
```

### INVARIANT ASH

A declared structural property survives the hostile family.

```text
INVARIANT_CANDIDATE
```

```text
INSUFFICIENT_TO_COMPARE
```

### UNRESOLVED

The family is too weak, correlated, or incomplete.

```text
UNRESOLVED
```

This is a lawful successful outcome.

## `RING-PRESSURE-001`

A relation ring is admitted only when crossings are typed:

```text
N1 --R1--> N2 --R2--> N3 --R3--> N1
```

Mere association does not close a ring.

Pressure a candidate ring by:

```text
shuffle visual layout while preserving graph
remove one claimed necessary edge
replace a relation with vague RELATED-TO
swap one decoder
hold nodes fixed while changing relation typing
hold graph fixed while changing presentation
```

If the ring disappears only when the picture is rearranged, it is likely a layout artifact.

If it survives graph-preserving shuffles but breaks when a necessary typed edge is removed, the relational structure has earned more attention.

## Stateless return null

The ringing pass gains one hard mathematical control.

For a pure deterministic stateless decoder:

```math

```

returning to the exact same source `x` and exact same decoder constitution `D` must return the same projection.

> **NO HIDDEN HISTORY, NO NONZERO HOLONOMY.**


If history is constitutive, model it explicitly:

